## 实施内容

1. **有界存储能力**：通过 `capabilities.boundedBackup=1` 声明摘要、分页、目标变更与暂存替换能力。批次同时计入条数、实际编码字节、结构节点；正常预算为 50 条、1 MiB、50000 节点。较大的单条记录单独发送，仍受现有单条及协议硬限制约束。
2. **日常事件增量**：已核对的聊天新增与目标编辑仅处理变更楼层；混合事件合并目标与新增楼层。初始载入、删除、未知目标或状态不一致走分批核对。不会把缺失编辑编号自动当作可信末层编辑。
3. **原子完整替换**：复用原有 transfer 暂存空间，以独立任务前缀记录进度；暂存不进入正式目录。核对数量、连续性、归属和数据区／revision 后，一次数据库事务发布。正式摘要仅合并本备份类型字段。丢失提交回执时查询任务结果；不可确认时不谎报未写入。
4. **来源与并发**：需要整份处理时固定原始消息副本，逐批 canonicalize；事件即时递增来源代次，提交前再次逐条比对。恢复保护写入后、实际改聊天前重验来源；保护回滚也使用提交修订，不能覆盖期间的新写入。日常备份开始前取消并排空此前核对副作用，避免自己的状态更新使暂存失效。
5. **摘要与懒加载**：目录按摘要分页；SQLite 直接统计，不取正文生成目录；IndexedDB 用游标累计。当前面板只加载摘要及有限 recent，完整恢复正文在预览入口分页读取。全部读取并验证后才生成／执行恢复计划。
6. **关联入口**：historical 不再读回正文计数；pending 读取及确认删除分批；recent 大替换保留事务。改名接续在存储侧游标处理；快照发布／删除取消全量键数组；快照临时指纹与比较逐消息处理。既有迁移任务流程保留。
7. **简单状态与清理**：保留原四个主要入口和现有弹窗。当前聊天更新／读取失败与整个存储不可用分开；后续保存核对不覆盖已有备份失败。新目录清理凭据使用已有 revision，执行时复核版本及保护规则。异常聊天标记并阻止清理，其余目录可显示。

未完成且已失效的暂存随后续写入按批清理；活跃暂存更新活动时间。提交回执保留一段时间供结果核对。暂存绑定原数据区与 revision，迁移锁存在时不能发布。

## 实际边界

- 手机验证是 Windows Edge 的设备视口／触摸模拟，不能等同于 Android、iOS 或 Safari 实机；本机没有 WebKit 测试引擎。
- 固定来源副本、完整恢复最终结果仍需占用本地内存；本次消除的是单次巨大传输及不必要的日常全量处理，并非无限大小承诺。
- 沿用已有全局 revision 保守判断并发变化；其他写入使版本改变时会拒绝旧暂存／读取，保留完整备份后允许重试，没有建立复杂的逐聊天版本或哈希索引。
- 无事件的静默修改在载入、返回页面、手动核对或异常接续时识别；不宣称每次只读新楼层还能立即发现所有静默修改。

本机实现仓库为 `.local-test/boxed-lllllabc-frontend-dev` 与 `.local-test/boxed-lllllabc-server-dev`。前端修改同步到原 Boxed 工作目录，原目录既有需求文档与 Git 历史不作重置。
