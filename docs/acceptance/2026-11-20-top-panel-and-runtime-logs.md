# 手机顶部操作区与运行日志（1.0.3 开发分支）

## 问题与修改

用户确认：空白出现在手机端“状态显示位置”为“聊天区顶部”时；1.0.2 只修复了扩展设置页中的同名操作区。

共用标题的说明文字使用 `flex: 1 1 15em`。窄屏切换为纵向排列后，15em 变成了纵向尺寸。之前的 `flex: none` 仅匹配设置页和弹窗的两个 ID，未覆盖 `boxed-lllllabc-status-panel-body`。

本次将窄屏修正应用到共用标题，并让顶部正文与其他两个入口一样从顶部按内容高度排布。保留顶部覆盖布局、现有面板高度上限、四个操作入口和面板内部滚动。

日志梳理发现以下歧义，并一起修正：

- 开放的分批读写、快照、保护记录核对和清理接口缺少中文名称，回退到“日常备份操作”。现在每个开放操作及存储任务步骤都有明确名称；已知备份类型时补充具体对象。
- “处理完成”未区分暂存批次、单个步骤和整项任务。现在分别说明“尚未提交正式备份”“本步骤完成”“任务完成”，不以存储请求完成代表酒馆聊天文件已保存。
- 分批写入结果按实际回执说明；已提交的任务收到撤销请求时显示“备份已经提交，未执行暂存撤销”；回执缺失不能当作未提交或已成功。
- 连接检查、读取取消、写入取消和结果未知分别提供处理指引；保留错误代码，并结合 SQLite 原生错误码说明锁定、只读、空间不足等情况。
- worker 已报告的同一次异常不再由路由另记为通用“备份请求”。未进入 worker 的校验、权限和排队错误仍由路由记录；记录器不可用时保留明确的终端提示。
- 启动阶段和排队/初始化等待时间单独保留，避免把总等待误认为某一楼层持续写入。
- 新字段只保留固定的备份类型、阶段和结果枚举、计数及耗时；不添加聊天名、正文、SQL、密钥或任意错误原文。前端上报接口继续拒绝这些内部诊断字段。

前后端共享同一份日志文案和格式化实现。浏览器沿用设备本地时间，后端调用时明确选择 UTC；原始日志时间仍为 UTC，不重写历史文件。

- Edge 加载隔离酒馆 1.15.0 的实际 CSS 和当前扩展模块，检查 360×640 竖屏、800×390 横屏、1200×900 桌面下的顶部面板、设置面板和状态弹窗，共 9 组。
- 修复前 360px 顶部说明区域高约 175.5px，文字到按钮间距约 168.5px；修复后说明区域约 16.4px、间距约 9.4px。其他入口未复现大块空白。
- 四个按钮保留、无横向溢出、按钮高度至少 44px；顶部高度不超过现有限制。360px 顶部面板模拟触摸后正文滚动 105px。
- 前端 352/352、后端串行 150/150、真实 SQLite 安全专项 19/19 通过；新增日志覆盖所有开放操作、步骤与任务区分、回执语义、错误指引、重复错误抑制和日志上下文隐私。
- `git diff --check` 及修改模块语法检查通过。机械样式检查的 10 项提示均指向既有边框，不属于本次间距修改；本次按原有视觉样式做窄范围修复。

测试入口为 `tests/browser/run-current-chat-layout.mjs`（默认 `after`）。通过 `BOXED_HOST_PUBLIC` 指向隔离酒馆的 `public`，`BOXED_PLAYWRIGHT_PATH` 指向本机 Playwright 模块；`BOXED_BROWSER_PATH` 可指定浏览器，`BOXED_LAYOUT_ARTIFACTS` 可指定输出目录。它只启动独立静态测试服务，不连接真实酒馆 API。

本机布局与日志证据位于 `.local-test/current-chat-layout/`：`before.json`、`after.json`、各视口截图、`frontend-tests.log`、`server-tests.log`、`storage-safety.log`。最终日志细项补测见 `final-log-tests.log`、`final-route-tests.log`。

手机浏览器和触摸为桌面设备模拟，不能代替 Android/Termux、iOS/Safari 实机验收。本次没有读取或修改真实聊天、备份数据库；存储协议、数据库 schema 和版本 1.0.3 均不变，继续使用同名开发分支 `codex/1.0.3-backup-race`。
