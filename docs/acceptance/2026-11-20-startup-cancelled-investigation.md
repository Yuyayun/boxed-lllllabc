# 欢迎页 cancelled 日志排查（1.0.3 开发分支）

用户反馈：前后端切换至 `codex/1.0.3-backup-race` 后，仅停留欢迎页，未进入聊天。服务器出现耗时 51.4 秒的 `cancelled`，旧日志将操作显示为“日常备份操作”和“备份请求”。打开 Termux 小窗前没有其他操作。

## 已确认的代码路径

- 欢迎页启动也会通过 `switchUi.refresh()` 调用服务器 `/status`，选择服务器存储时还会刷新存储概览。`/status` 等待数据库初始化、检查数据库读写能力和容量，不读取当前聊天正文。
- 备份协调器在当前聊天身份无效时返回 `identity-missing`，不会为欢迎页建立楼层备份或写 pending。已有协调器测试覆盖这一边界。
- `/status` 对应 worker 操作为 `_status`。原日志格式未包含它，落入“日常备份操作”的兜底；路由异常另记为通用“备份请求”。因此原截图没有保留足够信息来确认具体 operation。
- worker 的外部取消来自路由 HTTP 请求中止或响应连接提前关闭；worker 无进展期限默认 120 秒，触发时先返回 `outcome-unknown`。worker 统计的耗时从排队开始，包括初始化等待，51.4 秒不代表在写入某一楼层 51.4 秒。
- 前端 15 秒期限是收包空闲期限；收到心跳后会重新计时。不能仅凭耗时判断为固定 15 秒或 120 秒超时。

## 本次修改

前后端日志将 `_status` 显示为“检查服务器存储”；该操作的 `cancelled` 显示“本次连接检查已取消，可重新检查服务器连接”。路由层状态检查异常也保留 `_status`，便于下一次现场日志确认实际对象。写入操作的取消继续保留核对结果的提示。

这次调整日志和测试，没有修改数据库启动校验、超时、取消规则或备份写入逻辑；不能将日志改善称为已修复现场断连。

## 验证及未确认部分

- 真实 HTTP 路由测试：初始化尚未完成时持续返回心跳，完成前不返回成功，完成后返回连接结果；只执行 `_status`。
- 真实 HTTP 路由测试：主动断开检查连接，服务器收到取消信号并记录明确的检查错误；下一次检查可正常连接。这里的断连是测试注入，不能证明用户做了断连操作。
- 日志回归：连接检查取消与 full 写入取消分别提示；不放宽写入成功判定。
- 使用本机酒馆现有 `compression` 中间件加前端真实客户端的独立 HTTP 探针，正常延迟完成未复现取消；没有证据归因于默认压缩中间件。探针未使用真实聊天或备份库。
- 完整前端测试 348/348、完整后端串行测试 148/148 通过，`git diff --check` 通过。日志在本机 `.local-test/historical-restore-investigation-20261119/frontend-startup-log-tests.log` 和 `server-startup-log-tests.log`。
