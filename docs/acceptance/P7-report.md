## 实现与影响文件

压力前确实复现问题：175 段聊天、4,373 条普通记录、263,450,643 字节估算内容，IndexedDB 目录能读，SQLite 旧整包读取返回 `too-large`。不能把这个失败记作“压力通过”。

修复为**一致事务内按聊天读取、返回紧凑目录摘要**，不把全部消息正文跨 API 发送到浏览器。批量清理在同一读写事务中通过同一摘要重核范围、原指纹、元数据与保护状态，再调用既有删除内核。未改原四类备份算法、同步方式、多账户策略或旧端清空算法。

前端提交包含 12 个明确文件：

- `src/storage/catalog-reader.js`：逐聊天读取、统计未进入索引的异常行、合并摘要；失败不回退到旧整包请求。
- `src/backup/catalog.js`：提取共用摘要汇总，原统计/排序/指纹语义保持。
- `src/storage/operations.js`、`src/db/index.js`、`src/storage/indexeddb-adapter.js`：接入摘要端口，批量事务复用；IDB 读取索引键和总数以防遗漏异常记录。
- `src/controllers/catalog-controller.js`、`src/controllers/storage-controller.js`：目录/预览/概览使用摘要；保留测试驱动兼容。
- `src/storage/protocol.js`：协议 5，新增受限 `getBackupCatalog`。
- `tests/catalog-reader.test.js`、`tests/browser/p7-stress-contract.js`：等价性、异常行、无回退及压力契约。
- `README.md`、`CHANGELOG.md`：配套版本、限制、安装/更新与已测范围。

独立后端提交 11 个明确文件：`README.md`、`CHANGELOG.md`、`package.json`、`src/router.js`、`src/sqlite.js`、`tests/batch-cleanup.test.js`、`vendor/frontend/ORIGIN.json` 和共用 `catalog.js`、`catalog-reader.js`、`operations.js`、`protocol.js`。

当前协议 **5**、后端 **1.0.0-dev.5**；IndexedDB schema **7**、SQLite schema **3** 不变。只有新摘要/批量事务按聊天和类型读取时使用每次 128MiB/25,000 条预算；旧整包 32MiB、单条 8MiB、请求 16MiB、工作线程 15 秒等限制保留。超限明确拒绝，不截断后删除。不是任意大小单聊天或记录均无限可用的保证。

## 大数据与资源实测

数据固定 175 段虚构聊天、4,373 条普通备份，消息填充主体 262,380,000 字节，总目录估算 263,450,643 字节；字段包括中文名称、候选回复、选中状态、Date、null、undefined。主体为可压缩的合成文本，不是复制真实聊天，不保证高熵内容具有相同网络耗时。

| 项目 | 1.15.0 | 1.19.0 |
|---|---:|---:|
| 修复后 IDB 摘要读取 | 3,848ms | 3,729ms |
| 修复后 SQLite 摘要读取 | 4,559ms | 4,408ms |
| 175 聊天目录渲染 / 搜索 | 35 / 5ms | 30 / 5ms |
| 创建 100 份快照 | 561ms | 644ms |
| IndexedDB → SQLite 完整切换 | 64,650ms | 64,477ms |
| SQLite → IndexedDB 完整切换 | 66,805ms | 63,313ms |
| IDB 预览 / 执行与刷新 | 4,664 / 7,540ms | 4,941 / 7,608ms |
| SQLite 预览 / 执行与刷新 | 5,012 / 7,670ms | 4,801 / 7,790ms |
| 压力期间主页请求采样最大耗时 | 22ms | 25ms |

两版都逐项验证：**每端删除 3,028 条、保留 1,345 条受保护记录和 100 份完整快照**；源副本保留、目标替换、读回及内容摘要验证通过，页面运行错误为零。批量失败与过期行为由独立故障契约另验，不用成功压力案例替代失败测试。

1.15.0 服务端工作集采样最大 360,947,712 字节（约 344MiB）；原浏览器采样只覆盖启动时进程集合，**不能当作完整浏览器峰值**。1.19.0 改为每次从该测试浏览器的 CDP 查询动态进程集合，再采样工作集，服务端最大 577,138,688 字节（约 550MiB）、浏览器进程工作集总和最大 1,027,686,400 字节（约 980MiB）。这是约 1 秒周期的采样最大值，不是精确瞬时峰值；浏览器多进程工作集相加也可能重复计算共享页。两个浏览器口径不同，不能直接据此比较版本优劣。

另有只读阶段 CDP JS heap：旧 IDB 整包读结束约 561MB，摘要读结束约 39MB；这是操作结束时读数，**不是峰值**。资源监测、录制浏览器与测量工具自身也会带来开销。主页响应时长不是事件循环延迟指标。

1.19.0 的实际主进程事件循环测量见 `p7-eventloop-119.json`：使用仅装在隔离实例的临时 `perf_hooks` 探针，连续三次读取剩余约 81MB 的受保护目录，共约 5.05 秒；主循环延迟 p95 **16.31ms**、采样窗口最大 **20.28ms**、利用率约 **1.92%**，进程累计用户/内核 CPU 用时约 907/250ms。该结果是指定负载下的观测，不是任意负载的上界。探针测完移出插件目录，端点已移除，不属于产品或两个仓库提交。

## 兼容验证中的测试脚本修正

- 1.19.0 加强了原生聊天完整性保护。快速脚本切换角色后，原生角色缓存曾回到旧文件名，保存被正确拦截；没有输入 OVERWRITE 或强制保存。验收脚本改为通过原生 `updateRemoteChatName` 绑定目标、打开已存在的虚构聊天后再测，随后全部通过。未为此修改酒馆源码或箱装备份算法。
- 1.19.0 自带 `plugins/package.json` 和 `.gitkeep`。旧“插件目录完全为空”断言把宿主元文件误判为已安装插件；改为允许这两份宿主文件，同时严格拒绝插件目录或额外代码，再执行无插件恢复通过。
- 迁移锁定脚本此前依赖备份总开关已开启，空来源没有 append 批次；改为显式建立虚构来源记录后验证锁定。未改产品锁逻辑。
- 主动原生删除按既有完整备份规则重建，异常缩短才冻结；验收脚本保持这一语义，没有把主动删除误当必须冻结。

这些初次失败和重试日志保留，最终表使用修正后的真实结果；不把脚本错误隐藏成产品“首次全过”。
