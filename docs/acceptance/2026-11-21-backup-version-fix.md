# 1.0.4 正文版本回归修复验收

日期：2026-11-21。前后端从各自 1.0.3 的 main 创建 `codex/1.0.4-backup-version` 完成修复与验收，并配套发布 1.0.4。正式入口见[发布核对](release-1.0.4.md)。

## 问题与修复

1.0.3 的普通事务默认把所有可访问的备份 store 都列为已写入。current/new 身份核对只更新 chat_meta，仍会抬高 recent/full/historical/pending 四类版本；无实际迁移、空写入、无删除核销和只删除单类型的旧批量清理也有类似问题。原档可完整读回，但分页期间的这些操作会制造 backup-version-changed。

- IndexedDB mutation driver 在成功 put、delete、游标 delete/update 时记录实际写入的 store。删除不存在的键或空集合不记为变化。事务结束时同一类型只增加一次版本，与正文一同提交、回滚。
- SQLite 普通事务采用相同规则；SQL 删除以受影响行数判断。身份迁移无需另写容易漏分支的版本声明。
- 分批操作统一跟踪正式正文的 put/deleteChat，提交前暂存和撤销不记为正文变化。空提交和空删除不增加版本；批量清理多个聊天的同一类型只增加一次。
- 完整预览读取 full + pending，历史预览读取 historical + pending，recent 预览读取 recent + pending，pending 预览和请求保存读取 pending；恢复中心仍读取全部类型。缺省数组同步处理。
- fullWriteGuard 仅在涉及 full 的整组读取中比较；写入时的冻结/事件保护照常生效。保留真实正文修改检查、三轮有界重读、全局兼容 revision、数据区/迁移 epoch 和 pending 副本核销证明。

这里的写入是实际执行成功的记录 mutation，包括完整消息对象、候选、归属、哈希等；未增加全库比较，也不承诺将完全相同的重复 put 优化成不写入。

数据库 schema、协议和数据格式不变，无需清库、重新迁移或覆盖 frozen 原副本。类型版本仍是全库按类型计数，其他聊天真实修改同类型时仍可保守中断读取。

前后端合同文件保持一致：`tests/contracts/backup-version-contract.js`。后端通过 `tests/backup-versions.test.js` 运行，浏览器通过 `tests/browser/run-backup-version-contract.mjs` 运行。普通接口移除 writeStores 声明，版本由 driver 观察实际 mutation。

浏览器 SQLite 补测通过真实前端客户端、HTTP 路由、工作线程和 SQLite，检查第 26/1116 层 user 编辑在来源中断后接续、分页期间核销、预览失败保留保存状态，以及保存窗口加载中/打开后核销两种场景的实际按钮确认。测试中的酒馆聊天读取、渲染和 saveChat 是隔离夹具，不等同于运行真实 SillyTavern 原生聊天文件保存流程。数据库和浏览器上下文使用不同的合成聊天身份，避免同一服务器上的前后测试误用旧数据。

补测命令：设置 `BOXED_PLAYWRIGHT_PATH` 与可选的 `BOXED_BROWSER_PATH` 后运行 `node tests/browser/run-backup-version-contract.mjs`；额外设置 `BOXED_SERVER_REPOSITORY` 指向配套后端时，自动使用浏览器 SQLite 链路并执行上述 6 项补充场景。

本地原始日志保存在工作区 `.local-test/review-1.0.4-20261121/`，不进入安装包；浏览器 SQLite 补测见 `browser-sqlite-ui.log`。手机测试为桌面 Edge 触摸模拟，不能代替 Termux / Safari 实机结果，合成数据也不能证明用户现场数据库的内容完整。

## 后续使用观察

本轮自动验收已完成，不要求额外跑清单或反复恢复原档；手机实机与现场原库未检查的边界如实保留。后续正常使用如再出现异常，再保留原库做针对性排查。配套更新无需清库或解冻原备份；真实内容持续变化时仍可能合理要求重新预览。
