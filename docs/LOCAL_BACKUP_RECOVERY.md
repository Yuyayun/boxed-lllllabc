# 本地备份故障处理与救援文件

适用于前端开发补修 1.0.5-fix.2。正常更新保留现有备份，不需要清理站点数据或同步升级后端。

## 故障时怎么处理

扩展设置的“备份存放位置”中，本地读取故障会显示“处理本地备份故障”。该入口不依赖备份目录成功加载。优先点击“重新检查”：临时性读取故障最多额外尝试两次，相同请求合并；持续失败后停止反复读取，关键读取失败会暂停备份写入。只有目录异常时，当前聊天仍可用的备份读写继续工作。

重新检查会逐项核验原来失败的读取，只清除已成功的项目。目录或快照列表仍失败时保留提示，不会因此阻止健康的当前聊天备份；关键读取恢复后，其他尚未恢复的关键读取仍会维持写入保护。已确认回滚的写入失败按原流程报告，不当作未知提交；任务凭证确认也不会顺带解除其他独立故障。

写入不会因故障自动重试。大批量提交可核对原任务的 committed 凭证；没有可信凭证的未知写入结果保持暂停，单独重连成功不能证明旧操作已完成。此时仍可只读救援或明确放弃旧本地数据后重建。

### 尝试只读救援

救援以数据库实际已有版本打开；不存在旧库时中止，不创建空库，也不升级旧库。救援按物理对象存储的主键分页，不使用聊天二级索引，不写原库、不切换数据区、不清理暂存。每张表独立读取；一张表失败不妨碍其他表。表与分页读取都可能失败，不能承诺修复浏览器底层故障。

每卷约 4 MiB 或最多 10000 条原始记录；单条较大的记录可独占一卷，仍受既有单条 8 MiB 和结构上限约束。界面一次只保留当前卷，点击“下载第 N 卷并继续”后再继续扫描，最后下载救援清单。请检查浏览器确实保存了这些文件；扩展不能核验设备下载目录。取消后保留原库，已下载的卷仍可读取；未提供下载的数据不算已导出。

文件含私密聊天正文，可能包括同一酒馆站点曾使用过的多个账号的本地记录。本次不按账号分区，不上传文件，也不要求将文件发送给开发者。

### 清除旧本地备份并重建

不需要完成救援或导出才能选择重建。必须勾选接受丢失旧备份，并点击“删除旧备份并重建”。范围是当前浏览器、当前站点的整个 `boxed-lllllabc` 数据库：两个数据区、所有聊天的四类备份、未保存变更、快照和暂存任务都会永久删除。它不影响酒馆服务器原始聊天、角色卡、扩展设置、其他数据库或后端 SQLite；独立的 `boxed-lllllabc-control` 存储位置登记也保留。

当前使用 SQLite、控制记录不可核验、存在未完成迁移或无法取得跨页独占权时，不执行删除。请先处理原存储任务或关闭其他酒馆页签，不能通过清除控制库强行解锁。

删除提交前可以取消。提交后没有可直接撤销该请求的接口；其他页签占用时会继续等待，关闭提示不代表撤销删除。必须等删除成功，再建立并验证新的 v9 空库。旧缓存和旧预览会失效，后续按原设置备份当前仍存在且可读取的聊天，不自动遍历全部服务器历史聊天。

重建空库不等于恢复过去的未保存变更、历史副本、已删除聊天或快照，也不等于当前聊天已经完成首轮备份。请查看随后显示的实际备份结果。如果删除、新建或核验失败，扩展会说明失败阶段并保持相关写入暂停，不反复删库。浏览器存储服务异常、权限或空间问题可能需要完全退出浏览器、重启设备或腾出空间；不要清理整个酒馆站点数据。

## 救援文件格式与读取

格式为 `boxed-local-rescue`，版本 1，独立于迁移协议；不能直接导入现有迁移或恢复入口。本次没有增加救援包导入或自动重建历史聊天的系统。

- `part-N.json`：记录卷，包含导出编号、卷号、站点、数据库名与实际版本、时间、逐条编码的 `{store,key,value}`，以及整个卷载荷的 SHA-256。
- `manifest.json`：最终清单，列出卷号、条数与摘要；各表的物理名称、数据区、读取数量、最后成功主键、扫描状态、失败原因与可取得的活动区/修订保护信息。暂存表和非活动区不能认定为正式备份。
- 记录使用已有 `encodeStorageValue` 标签树，保留 undefined、Date、BigInt、特殊数字和稀疏数组。循环引用、Map、Blob 等不支持的值会明确报错并使相应表标为部分/失败，不静默转成普通 JSON。
- `scanned` / `empty` 表示在可取得的保护信息和计数下完成扫描／确认空表；`unverified` / `partial` / `failed` 表示证据不足／部分可读／读取失败。`businessIntegrity: not-verified` 始终提醒：文件校验、扫描稳定不证明历史聊天备份业务上完整。旧库 revision 不变也不足以排除旧异常造成的内容缺失。
- `exportedRecords` 只统计已交给逐卷下载入口的记录；表的 `count` 是实际读取数量。取消或下载失败时，两者可能不同，最终卷列表是已提供导出部分的依据。

安装包内附无额外依赖的本地读取工具，需要 Node.js。在扩展目录执行，显式传入清单与属于它的全部数据卷：

```sh
node tools/read-local-rescue.mjs manifest.json part-1.json part-2.json
node tools/read-local-rescue.mjs --records manifest.json part-1.json part-2.json
```

默认只核验卷摘要、卷号和数量；`--records` 会在本地终端显示解码后的原始主键和完整记录，包含私密正文。只提供部分卷时可以单独核验和读取它们，但没有齐卷证明。任何文件摘要不符或与清单不一致都会报错，不自动改写或导入数据库。

## 验证边界

已知唯一方向空范围兼容风险和可捕获的事务异常可通过本补丁预防；这不等于已复现原 Arc Search 故障，也不保证救出浏览器底层完全不可访问的数据。自动化只使用独立测试上下文和合成数据；iOS/Arc Search 真机及用户现场原库需要另行验证。
