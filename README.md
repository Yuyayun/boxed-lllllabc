# 箱装辣白菜

## 1.0.0 开发分支：综合验收与大目录（P7）

目录不再通过服务器一次返回全部消息正文。新摘要端口在一致事务内按聊天读取普通备份，只返回统计、原有清理指纹和保护信息；IndexedDB 也采用同一摘要构建规则。批量清理在同一删除事务内复核整个范围，继续复用原指纹、保护和元数据补丁，失败仍整批回滚。

当前协议 **5**，配套可选服务器插件 **1.0.0-dev.5**；数据库结构保持 IndexedDB 7、SQLite 3。普通整包接口的 32MiB 限额保留；摘要与批量事务按聊天/类型读取，每次最多 25,000 条、128MiB，超限明确失败，不截断后删除。安装后端仍不切换或迁移，协议不兼容会安全拒绝 SQLite。

已在隔离 1.15.0 环境测得 175 段聊天、4,373 条普通备份、约 263MB 内容的目录、搜索、100 份快照、双向切换和批量清理结果正确；这是指定环境与样本的记录，不保证任意规模具有相同耗时。1.15.0 与 1.19.0 已分别验证四类普通恢复、快照、Rename、原生 Branch/Checkpoint、插件接口及保护流程；1.15.0 的共享 UUID 与 1.19.0 的新 UUID 分支均保持独立。前后端开发成果已分别推送至各自仓库的 `codex/1.0.0` 分支，[P1–P7 验收报告](docs/acceptance/README.md)已归档；尚未合并 main 或正式发布 1.0.0，真实手机和完整发布门槛尚未全部完成。

升级前等待生成和存储操作结束，关闭其他酒馆页签，并为重要数据另存副本。前端与服务器插件分别更新；只有需要 SQLite 才安装或更新后端。若活动端为 SQLite 而版本不兼容，先更新配套后端；不要删除控制库、任务锁或 SQLite 文件来绕过恢复。

## 1.0.0 开发分支：设置与目录布局（P6）

扩展设置保留原折叠标题、状态图标及展开内部的版本/扩展信息行，按单列排列「备份存放位置」「备份开关」「参数与显示」「聊天快照」「备份管理」「原存储位置的数据管理」。备份启用选项仍为原生勾选框，快照没有开关。「检查保存状态」仍检查酒馆原生聊天保存；「检查 SQLite 连接」只检查可选存储插件，不切端或迁移。

存储区区分 IndexedDB 的来源用量/配额估算，与 SQLite 的记录内容、文件及日志占用、服务器文件系统可用空间。未提供的指标明确标注，断线不显示为零占用或正常空库。旧端清理只有成功切换后才开放；有未完成操作、插件不可用或不可写时禁用并说明原因。

「全部聊天备份」目录在加载、长列表、空数据和失败状态下都相对当前可视视口居中。手机安全区留白对称，正文独立滚动，标题和关闭入口保持可达；监听 VisualViewport 的缩放、移动和尺寸变化，关闭时解除监听。保留统计、搜索、分组、单聊天与批量清理，并在重绘时保持可用焦点。颜色和透明度继续继承酒馆主题。

P6 当时保持协议 4 和后端 1.0.0-dev.4 不变；最新配套版本见上方 P7 说明。数据库结构未改，最终 1.0.0 发布验收尚未全部完成。

## 1.0.0 开发分支：批量清理（P5）

「查看全部聊天备份」保留原汇总、搜索、分组和单聊天管理，新增默认收起的「批量清理」。支持清除全部、单角色/群聊全部、单角色内多选、跨角色多选；多选使用独立的轻量列表，取消后回到普通浏览。目录搜索不会缩小“全部”或“单角色全部”的清理范围；实际范围以确认预览为准。

可选择最近、完整、历史三类普通备份。未保存变更、冻结或等待酒馆后端确认的完整备份始终受保护，预览会列出跳过原因。预览显示聊天数、可删除记录数、占用估算及保护条目，确认后在同一事务内复核整个选择范围；范围、记录、身份元数据或保护状态变化会拒绝旧计划，中途写入失败整批回滚。结果按“聊天 × 备份类型”列出成功、跳过、失败项数；连接中断导致结果未确认时应先刷新核对，再重新预览。

清理只作用于当前活动端的普通备份，保留聊天快照、非活动端、备份开关和酒馆原生聊天文件。后续日常聊天仍可能重新生成备份。此流程与独立确认的「清空原位置的备份」分开。

P5 引入协议 4 和服务器插件 1.0.0-dev.4；最新配套版本及大目录改进见上方 P7 说明。IndexedDB schema 7、SQLite schema 3 保持不变。后端仍可选，安装不会自动切端或迁移。不兼容版本拒绝 SQLite 操作，超限明确失败，不截断后删除。

## 1.0.0 开发分支：聊天快照（P4）

「当前聊天备份」提供主要的「创建聊天快照」操作；设置中的「聊天快照」提供独立的「管理聊天快照」。无需启用开关，即使普通备份总开关关闭，也可手动创建和恢复。名称默认填入当前时间，每次创建独立存档，保留全部消息字段、消息顺序、swipe 候选、选中状态及聊天元数据。存档内容不会随日常修改、普通备份恢复或普通清理改变；重命名仅修改快照名称。

管理窗口支持分页列表、完整内容校验后的分段预览、重命名、独立确认删除，以及预览后再次确认恢复。恢复前需打开快照所属聊天；Rename 会接续快照归属，原生 Branch/Checkpoint 保持独立，不会因共享旧 UUID 而继承父聊天快照。恢复使用酒馆现有重绘和保存接口，保留目标原生 UUID 与缓存身份，并实际读回酒馆保存内容核对。只改变界面、保存失败或核对失败时不会报告恢复成功；保护记录保留，源快照也保留。

快照跟随当前活动端保存，参与双向完整存储切换和独立确认的非活动端清空，不进入普通备份清理。大聊天逐楼层分批写入、完整后发布；未完成存档在管理窗口明确标注且禁止恢复，可单独删除。单条楼层及存档信息各遵守现有 8 MiB 记录限制，超限明确失败，不截断内容。

P4 将 IndexedDB 升级至 schema 7、SQLite 升级至 schema 3。升级保留旧普通备份，SQLite 升级前生成一致备份；当前兼容版本与剩余验收见上方 P5 说明。

## 1.0.0 开发分支：切换备份位置（P3）

设置中的「备份存放位置」显示当前活动端和可选 SQLite 连接状态。只安装前端仍默认使用 IndexedDB；安装或检查服务器插件不会切换、迁移或双写。SQLite 服务器插件独立维护于 [boxed-lllllabc-server](https://github.com/Yuyayun/boxed-lllllabc-server)。当前兼容协议及后端版本见上方 P7 说明。

「切换备份位置」支持 IndexedDB ↔ SQLite。确认后完整覆盖目标端已有箱装备份，经分页复制、逐项校验及事务提交后才切换活动端，成功后原来源副本保留。异常记录不会静默过滤；失败时保留原来源与原目标。「清空原位置的备份」仅在成功切换后针对已确认的非活动端开放，需单独确认，清空后读回验证；不删除活动端、箱装设置或酒馆原生聊天文件。

操作前停止生成、关闭其他酒馆页签。进行中对话框阻止当前页面聊天操作，箱装排空已有任务后暂停新写入；其他插件/外部程序直接修改无法完全拦截，提交前发现当前聊天变化则停止。跨页签使用浏览器 Web Locks，缺少该能力时拒绝切换。目标暂存与回滚副本需要额外空间；空间不足或校验失败不会报告成功。

刷新/重启时根据持久日志恢复：尚未激活则回滚原目标，已激活则收尾。恢复期间后端不可用时保持暂停并提供重试，不回退写入另一端。请保留两端数据和浏览器存储控制记录，不要通过删除记录跳过恢复。SQLite 活动时统计来自服务器数据库，浏览器配额不充当服务器剩余空间。

此处记录 P3 切换机制；聊天快照和当前开发状态见上方 P5 说明。1.0.0 最终发布验收仍待后续阶段。

`boxed-lllllabc` 是一个 SillyTavern 第三方前端扩展，用于核对当前聊天是否已经保存到酒馆后端，并在浏览器本地维护独立、可预览的聊天备份。

当前版本：`0.1.4`（正式版）

> 正式版已经完成 GitHub 安装、桌面端、千层完整聊天备份、记忆类扩展兼容、手机端全部备份弹层、版本提示和内置更新自动刷新验收。浏览器本地备份不能替代设备外部备份，重要聊天请继续保留你原有的备份方式。

## 主要功能

- 显示当前聊天的“正在检查保存状态”“酒馆聊天已保存”或失败状态。
- 状态灯可位于最新楼层内部或聊天区顶部；全屏聊天美化下，顶部状态会浮在顶栏下方，滚动中的楼层仍可从半透明状态层下经过。
- 当前聊天窗口始终保留“请求酒馆保存”“恢复备份”“检查保存状态”三个入口。
- 备份完整消息对象和全部候选回复，不把备份写入聊天正文或模型提示词。
- 通过角色头像文件名和 SillyTavern 当前 `chatId` 隔离备份；Branch、Checkpoint 和复制聊天即使内容相同，也会建立独立备份。
- 新版 SillyTavern 优先使用明确的 `CHAT_RENAMED` 事件定向接续改名前后的备份；SillyTavern 1.15.0 缺少该事件时，只有在同一角色或群组下恰好一个旧文件消失、一个新文件出现，并且聊天 `integrity` 或当前聊天完整内容一致时才接续。普通切换和 Branch 都不会触发迁移，证据不足则原样保留旧备份；目标身份已产生的少量同聊天记录会在同一事务中安全合并。
- 后端聊天读取和酒馆保存请求最多等待 15 秒；弱网超时后本地 pending 与备份继续保留，后台仍按 2 秒、5 秒、10 秒节奏核对，新核对会取消并隔离旧响应。“检查保存状态”仍只请求一次。
- 页面切到后台、重新可见或从页面缓存恢复时，先排空已排队事件，再刷新当前聊天备份状态；不会因此主动请求酒馆保存。
- 设置页可以查看本扩展的估算占用、当前酒馆来源已用空间和浏览器估算可用空间。
- 支持按角色或群聊分组查看全部聊天备份，并按聊天名称或角色名称搜索。
- 使用 SillyTavern 自带的 Git 扩展接口检测和执行更新；扩展不会自行下载或静默更新，用户确认更新后会自动刷新酒馆页面。

## 四类本地备份

| 类型 | 默认状态 | 用途 |
| --- | --- | --- |
| 最近楼层 | 开启，默认 20 层 | 保存当前聊天最近 N 层以及全部候选回复，可连续补回缺失的尾部楼层。 |
| 未保存变更 | 随正常聊天操作记录 | 保存尚未得到酒馆后端确认的新消息、编辑、候选切换和删除等变更。 |
| 完整聊天 | 关闭 | 为打开过的聊天维护从第 0 层开始的单份完整副本，可预览后整份覆盖恢复。 |
| 历史楼层改动 | 开启 | 修改最近 N 层之外的旧楼层时，保留该楼层的完整状态和全部候选回复。 |

完整聊天备份遇到没有明确删除事件的异常缩短时会冻结旧副本，不使用可能残缺的聊天覆盖它。

如果记忆、摘要等其他扩展持久化修改了已有楼层，完整备份会先保留原副本，待酒馆后端确认整份聊天与前端一致后再安全接续；不会按特定插件字段放宽校验，也不会丢弃这些扩展写入的数据。

如果已经检查并确认当前聊天内容正确，可以在“当前聊天备份”中处理冻结状态：经过两步明确确认后，选择采用当前聊天替换冻结副本并恢复更新，或只删除冻结的完整备份。这个入口不会发送、修改、删除或恢复 SillyTavern 聊天。

## 恢复与清理安全规则

- 所有恢复都会先展示差异、范围和冲突，再由用户确认。
- 确认时会重新校验当前聊天和相关备份；预览后内容发生变化会拒绝旧计划。
- 恢复后先保留 pending，直到后端读取结果确认一致才清除。
- 保存失败时保留前端恢复结果和保护记录；保存请求超时不视为失败，会转入后端核对。
- 最近楼层只补回当前聊天末尾的连续缺失部分，不插入或重排中间楼层。
- 历史楼层只替换当前聊天中相同编号的楼层。
- 完整聊天恢复只接受从第 0 层开始且楼层连续的完整副本。
- 清理一次只处理一个聊天的一种本地备份，不删除或修改 SillyTavern 聊天文件。
- pending 不能强制清理；冻结保护中的完整备份不能通过普通清理绕过保护，只能在对应的当前聊天中经过两步确认后处理。

## 安装

在 SillyTavern 的扩展管理页面选择“安装扩展”，输入：

```text
https://github.com/Yuyayun/boxed-lllllabc
```

安装完成后扩展会通过 SillyTavern 的安装钩子自动刷新酒馆页面，随后可以在扩展设置中找到“箱装辣白菜”。

开发时也可以把仓库放到第三方扩展目录：

```text
SillyTavern/public/scripts/extensions/third-party/boxed-lllllabc
```

## 基本使用

### 可选 SQLite 后端（1.0.0 开发中）

后端单独维护于 [Yuyayun/boxed-lllllabc-server](https://github.com/Yuyayun/boxed-lllllabc-server)，按其 README 自愿安装到酒馆服务器插件目录。前端不依赖它，未安装时继续正常使用 IndexedDB；安装、启用或连接后端都不会自动切换存储、迁移或同步数据。

当前开发分支已提供 SQLite 插件客户端及用户主动确认的「切换备份位置」，仍以 IndexedDB 为默认活动端。后端只支持默认用户或单个启用账户，具体 Node/酒馆兼容性及开发版本状态以独立后端仓库说明为准。

### 当前备份操作

1. 打开扩展设置，确认“启用本地备份”已经开启。
2. 根据需要设置最近备份层数；完整聊天备份默认关闭，可自行开启。
3. 打开任意聊天，通过最新楼层状态灯、魔法棒菜单或扩展设置进入当前聊天备份窗口。
4. 使用“检查保存状态”读取酒馆后端保存状态。
5. 需要恢复或清理时，先阅读预览中的影响范围，再决定是否确认。

扩展不会自动替你恢复、删除、覆盖或请求酒馆保存聊天。

## 本地存储与隐私

- 备份保存在当前浏览器来源的 IndexedDB 数据库 `boxed-lllllabc` 中。
- 备份不会自动同步到其他浏览器、设备或 SillyTavern 安装。
- 卸载浏览器数据、清理站点数据或更换设备可能同时删除本地备份。
- 浏览器报告的空间配额是整个 SillyTavern 来源共享的估算值，不是本扩展独占空间。
- 空间不足时，本次写入会明确显示失败；扩展不会为了腾出空间自动删除已有备份。
- 读取到结构异常的本地记录时，扩展会将其从恢复列表中隔离，但不会擅自删除原记录。

## 更新

每个浏览器标签页会话只通过 SillyTavern 原生接口检查一次 Git 版本。没有更新或检查失败时不显示提示；发现远程更新后，标题旁会出现小型提醒，信息栏右侧保留由用户决定是否执行的更新按钮。

扩展信息弹窗提供 GitHub 和更新日志两个纯图标入口；更新日志只读取扩展随包附带的 `CHANGELOG.md`，按当前安装版本在原弹窗内展开，不访问额外的远程服务。

确认更新前请先等待当前回复生成结束，并完成手头操作。更新完成后扩展会先排空已经排队的备份事件，再自动刷新酒馆页面使新版本生效。

## 当前不提供

- 全局导入导出。
- 绕过保护规则的强制清理。
- 中间楼层插入、重排或猜测式结构恢复。
- 多版本历史时间线。
- 独立于 SillyTavern 的自动更新器。
